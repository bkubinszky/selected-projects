Sequential Multi-Agent Workflow

A local multi-agent workflow to practically explore agent roles, sequential orchestration, and structured handoffs

Date
2026-Aug
GitHub

Overview

Problem

How can several specialized AI agents be coordinated effectively and their results passed on in a structured way? The goal was to explore agent collaboration and sequential orchestration through a practical experiment.

Approach

I chose a simple, fictional Product Idea Stress Tester as the use case. Using CrewAI, I built a local workflow with three specialized agents that build on each other's results and use a language model running through Ollama.

Outcome

A working PoC that analyzes product ideas, critically challenges assumptions, and proposes validation experiments. The structured results are validated and presented in a CLI report, without requiring paid LLM APIs.

Implementation & Workflow

The PoC uses CrewAI to sequentially orchestrate three specialized AI agents: Product Strategist, Skeptic, and Experiment Designer. Each agent has a clearly defined task and builds on the results of its predecessors. All language model calls run locally through Ollama. Structured outputs support the handoffs between agents and are ultimately combined into a CLI report.

01

Why multiple specialized agents?

I wanted to explore how several AI agents could work together effectively. I chose three different perspectives: a Product Strategist to analyze the idea, a Skeptic to challenge its assumptions, and an Experiment Designer to propose validation steps. The focus was on understanding agent collaboration, not building an unnecessarily complex solution.
02

Why sequential orchestration?

For my first multi-agent PoC, I deliberately chose a straightforward sequential process. Each agent receives the results of its predecessors and builds on them. This makes it easier to examine context handoffs and dependencies without introducing the additional complexity of parallel or hierarchical workflows.
03

Why a local language model?

I wanted to run the test without external LLM APIs and also test the effectiveness of local models. Ollama allowed me to run an open-weight model locally and experiment with different configurations without ongoing API costs.
04

Why structured handoffs?

Because the agents build on each other’s work, their outputs need to be clear and consistent. I therefore used defined output formats and validation to make the results easier to pass as context between agents and ultimately combine into a consistent CLI report.
01

Clearly defined agent roles

Using multiple agents doesn’t automatically create a meaningful multi-agent workflow. What matters are clearly defined responsibilities and genuine dependencies between the agents’ outputs.
02

CrewAI

CrewAI simplifies much of the technical orchestration. However, the quality of collaboration still depends on how precisely agent roles, tasks, context, and expected outputs are defined.
03

Local language models

Even more complex agent workflows can run locally without paid LLM APIs. Smaller models particularly benefit from clearly defined tasks and well-structured prompts.
04

Structured outputs

When agents build on each other’s results, consistent and validated output formats become especially important. They simplify downstream processing and reduce errors during handoffs.
01

Alternative orchestration models

Explore hierarchical and other agent orchestration approaches alongside the sequential workflow. I’m particularly interested in understanding when the added complexity provides genuine value.
02

Observability & monitoring

Capture and visualize intermediate results, execution times, and context handoffs to better understand the behavior of individual agents and the overall workflow.
03

Additional use cases

Apply the existing architecture to other tasks and explore how effectively agent roles, task definitions, and orchestration patterns can be reused.
