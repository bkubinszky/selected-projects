Problem statement & Goal

With new product or business ideas, there is often an immediate impulse to start thinking about features and technical implementation. At the same time, key assumptions about the problem, target users, value, or actual demand often remain untested. The goal of this project was to build a local AI system that analyzes ideas in a structured way, challenges them critically, and derives concrete next steps for validation.
  • → Critical assumptions are made explicitly visible.
  • → Weaknesses and unnecessary product complexity are challenged early.
  • → Validate before investing time in development.
Objective

“Rather than having a single AI simply evaluate a product idea, the goal is to let several specialized perspectives build on each other to reveal risks, assumptions, and meaningful validation steps early.”

Approach & Workflow

The application is based on a sequential CrewAI workflow with three clearly separated roles. A Product Strategist first structures the idea and its most important assumptions. A Skeptic then deliberately challenges this analysis before an Experiment Designer derives the simplest and most cost-effective validation experiments possible. All agents run fully locally via Ollama and use the outputs of previous steps as context. The results are validated and then presented as a compact CLI report.
Step 1: Input
Describe the product or business idea
Step 2: Strategy
Structure the problem, target users, value, and key assumptions
Step 3: Challenge
Critically challenge assumptions, risks, and unnecessary complexity
Step 4: Validation
Design fast and cost-effective validation experiments
Step 5: Report
Combine the results into a structured overall assessment

Key Learnings

01
Agent Roles

Multiple agents only provide real value when their responsibilities are clearly separated and they deliberately build on the results of previous steps.

02
Critical Perspective

The Skeptic is particularly valuable because it does not simply produce a second analysis, but specifically challenges the assumptions made by the Product Strategist.

03
Structured Outputs

Structured and validated outputs make the workflow significantly more reliable and enable consistent processing of the agents’ results.

04
Local Models

Even a small local model can produce useful results for clearly defined agent tasks when prompts, roles, and output formats are sufficiently precise.

05
Scope

For the MVP, a well-designed CLI report is entirely sufficient. An additional user interface would initially have added little value to the core functionality.

Enhancement Ideas & Considerations

01
Streamlit Interface

A simple graphical interface for entering ideas and displaying the analysis if the CLI workflow should later become more accessible.

02
Comparison Mode

Analyze multiple product ideas using the same criteria and compare their key assumptions, risks, and validation effort.

03
Evaluation Profiles

Define different analysis focuses for digital products, services, internal tools, or new business models.

04
Model Configuration

Make local models interchangeable to compare the quality, speed, and resource requirements of different open-weight models.

05
Iterative Analysis

Run an existing analysis again after initial validation results and update assumptions, risks, and MVP recommendations accordingly.
